# 启动前验证清单与风险 — Gen4 宝可梦 Godot 4 浏览器/PWA 项目

> 大规模生成游戏逻辑代码前，以下验证必须全部通过。任何一项失败，需调整路线而非硬闯。

## 1. 启动前验证清单

- [ ] **PWA 导出链路跑通**：空 Godot 4 项目成功导出为 Web + PWA，在浏览器中可安装、可离线打开，图标与显示模式正确。
- [ ] **浏览器双屏性能基线**：目标浏览器中创建两个 `SubViewport`（基础 3D 场景 + 2D UI），记录帧率、填充率、Draw Call。**浏览器端目标 ≥30fps**；若开启线程支持，确认服务器 CORS 头可配置。
- [ ] **模型动画测试**：至少一个带骨骼动画的宝可梦 glTF 模型在 Godot 4 Web 导出中正确播放 `apicula` 转换的动画，且未触发“材质纹理动画”限制。
- [ ] **数据加载原型**：用 romkit 输出的 JSON 编写最小 GDScript 加载器，在浏览器中测量启动加载耗时与查询耗时，确认可接受（必要时异步加载或预编译二进制）。
- [ ] **战斗系统参考基线**：审阅 Godot 论坛教程的架构部分，确认战斗逻辑层类边界与接口设计方向。
- [ ] **OpenCode 环境连通**：LSP 桥接（如 `opencode-godot-lsp`）或 MCP 插件已配置，Agent 能读取 Godot 项目结构并执行基础编辑器操作。
- [ ] **法律边界确认**：项目定位与资产分发策略已写入 README 草案。

## 2. 全局风险与约束

| 风险 | 说明 | 缓解措施 |
| :--- | :--- | :--- |
| 浏览器 3D 性能 | 双屏渲染叠加 WebGL 2，填充率压力大。 | 降低 3D 视口分辨率；LOD；合并材质；持续测量帧率与 Draw Call。 |
| 线程支持依赖服务器头 | `SharedArrayBuffer` 需要 COOP/COEP 头。 | 启动前确认部署环境；不可配置则放弃线程支持。 |
| PWA Service Worker 路径 | 可能出现 service worker 文件名不匹配。 | 导出后检查实际文件名并调整注册路径。 |
| apicula 动画限制 | 部分形态变化动画不被 glTF 转换器支持。 | 选型前逐个验证；必要时离线烘焙替代动画。 |
| 数据解析性能 | 大型 JSON 同步解析可能阻塞。 | 异步加载、预编译二进制、分块加载。 |
| 法律风险 | 任天堂对 IP 同人项目态度积极。 | 代码开源、资产自备、非盈利、避免公开分发含原版素材的构建。 |
| Agent 生成代码冲突 | 多文件生成可能产生不一致实现。 | 维护 `docs/architecture.md` 作为契约；逻辑与渲染分离；改核心接口前先更新文档。 |

## 3. 通过后的工作方式

- 数据层优先：先跑通 romkit 数据加载与查询原型。
- 逻辑层保持纯 GDScript 类；渲染层只做表现。
- 双屏使用 `SubViewport`；触摸输入映射到下屏并处理坐标变换。
- 模型转换走 `apicula` 离线管线，禁止运行时解析 NSBMD。
- 仓库只保留代码、工具脚本与文档；不提交原版资产。
